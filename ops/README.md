## 完整时间线（重要：有三件事必须在灌真实数据之前做）

手册里有三条带**时间约束**的要求，分散在不同文件里。拼起来是这样：

```
① 服务能跑起来（还没有任何真实数据）
        │
        ├─ ★ 拔盘演练         层 5 的 verify 第 3 条
        │    卸载外接盘 → 确认服务报"找不到媒体"而不是数据库崩溃 → 重挂 → 自行恢复
        │    ⚠️ 只有在还没有真实数据时做才安全，之后就没机会了
        │
② 配开机自恢复                ops/boot-persistence.md
        │
③ 真断电，走冷启动验收清单      ops/cold-start-acceptance.md
        │    ⚠️ 不重启验证的自启动配置，等于没配
        │
④ ★ 备份配好，并【验证过能恢复】  ops/backup.md
        │    ⚠️ 必须在灌真实数据之前完成
        │
⑤ 这时候才灌真实照片 / 媒体
```

**为什么④要在⑤之前**：等有了数据再配备份，中间那段时间的数据是裸奔的，
而事故不挑时间。而且**没验证过恢复的备份不算备份**——
验证恢复这件事，在没有真实数据时做起来也最轻松。

**为什么①里的拔盘演练不能推迟**：它要主动制造一次故障。有真实数据之后，
没人敢做这个实验——于是你永远不知道外接盘掉线时会发生什么，
直到它真的掉线的那天。
