# 局域网唤醒（WoL）

> 让一台关着的机器远程开机。**成功率取决于一串前置条件，任何一环没满足都是静默失败。**

## 原理

往局域网广播一个特制的数据包（"魔术包"），目标机器的网卡在关机状态下仍保持低功耗监听，
收到就触发开机。

关键推论：**魔术包必须能到达目标机器所在的二层广播域。** 这决定了它跨网段不工作。

## 前置条件清单

按从下到上的顺序确认，**每一条都可能是失败原因**：

- [ ] **网卡支持并启用了 WoL**。有线网卡基本都支持；无线通常不行或很不可靠
- [ ] **BIOS/UEFI 里开启了网络唤醒**。选项名各家不同（Wake on LAN / PME / Power On by PCI-E）
- [ ] **操作系统关机时给网卡布了防**（关键是"布防"，不是"供电"——见坑典）
  - Linux：`ethtool <网卡>` 看 `Wake-on:` 是不是 `g`；不是就 `ethtool -s <网卡> wol g`，并做成开机持久化
  - Windows：**关掉"快速启动"**。它的"关机"其实是休眠，网卡状态可能不对
- [ ] **发包的机器和目标在同一个二层网络里**
- [ ] **交换机 / AP 没有丢弃广播包**。部分设备开了广播抑制或 AP 隔离

## 常见失败与对应

| 症状 | 多半是 |
|---|---|
| 从没成功过 | BIOS 没开，或系统关机时切了网卡电 |
| 以前能用，现在不行 | 系统更新重置了网卡电源设置；或换了交换机/AP |
| 局域网内能唤醒，从外面不行 | 魔术包跨不了网段——见下 |
| 唤醒后马上又睡了 | 唤醒和"保持唤醒"是两回事，睡眠策略要单独配 |

## 从外网唤醒

魔术包是广播，**跨不了路由**。三条路：

1. **组网工具**——但目标关机时组网工具也没在跑。所以需要**另一台常开的机器**
   在局域网内代发。这是最可靠的做法
2. **路由器的 WoL 功能**——很多路由器自带，但**这触及铁律①**，让用户自己配
3. 定向广播转发——复杂且很多设备不支持，不建议

**推荐第 1 种**：如果你已经有一台常开的服务器（跑着旁路由或其它服务），
让它当唤醒代理，从外面先连到它、再由它发包。

## 验收

```yaml
verify: |
  # ★ 必须从【另一台机器】发包，且目标处于真正的关机状态
  # 1. 确认目标已关机（不是睡眠——睡眠唤醒容易成功，会给你假信心）
  ping -c2 <目标IP>        # 期望: 不通

  # 2. 发魔术包
  wakeonlan AA:BB:CC:DD:EE:FF        # 或 etherwake / wol，按你装的工具

  # 3. 等待并确认起来了
  ping -c1 <目标IP>        # 期望: 30-90 秒内通
```

⚠️ **一定要在真正关机的状态下测。** 从睡眠唤醒的条件宽松得多，
测睡眠唤醒成功不能证明关机唤醒可用——而你真正需要的往往是后者。
