# 层 7 · 内网寻址

> 服务装好了，**怎么访问它？**
>
> ⚠️ **这一层所有人都要读**，和层 2/3/4/6 不同——那几层可以整片跳过，这一层不行。
> 只要你装了任何一个要被别的设备访问的服务，就得回答这个问题。

## 为什么"记 IP"撑不住

起步时用 `http://192.0.2.10:8096` 完全没问题。但它会在四个地方崩掉：

| 什么时候 | 发生什么 |
|---|---|
| 装到第五个服务 | 你要记五个端口号，家里人一个都记不住 |
| 服务器 IP 变了 | 每台设备、每个 App 里填的地址**全部失效** |
| 想上 HTTPS | 证书**签不给 IP 地址**（自签除外，而自签浏览器会拦） |
| 换机器 / 迁移 | 所有客户端都要重配一遍 |

第三条是硬的：**有些服务不上 HTTPS 就不能正常工作**——
比如密码库的客户端需要安全上下文才能解锁
（[`services/vaultwarden.md`](../services/vaultwarden.md#必须是-https)）。
这类服务会直接把你推向"必须有域名"。

## 枚举

| 值 | 做法 | 何时用 |
|---|---|---|
| `ip-static` | 主路由绑定固定 IP，客户端记 `IP:端口` | **起步默认**，一两个服务够用 |
| `hosts-file` | 每台客户端手工写 hosts | 止血用，别当方案 |
| `mdns` | `主机名.local` 自动发现 | 顺带能用，但**覆盖不全** |
| `lan-dns` | 局域网 DNS 给内网域名解析 | **服务多起来之后的正解** |

四种可以叠加，所以 `addressing` 是多值字段。

---

## `ip-static` · 固定 IP

**先做这个，它是其它三种的地基。** 服务器的地址不稳定，后面配什么都是白搭。

做法见 [层 2 · 静态 IP 怎么来](2-gateway.md#静态-ip-怎么来)——
那一节对"服务器主机"和"旁路由"同样适用。

> ⚠️ **不做旁路由的人也要做这一步。** 很容易漏，因为静态 IP 通常被当成"旁路由的需求"。

---

## `hosts-file` · 客户端硬编

在每台客户端的 hosts 文件里写死"名字 → IP"。

- ✅ 立刻生效，不依赖任何服务
- ❌ **每台设备都要做一遍**，手机和电视基本做不了
- ❌ IP 变了要挨个改

**当止血手段用**：某台机器解析出问题、你要立刻恢复访问时，它最快。
**别当方案**——设备数一多就是维护灾难。

⚠️ 硬编过的条目**退役设备时要记得清**，否则会留下指向不存在设备的解析。
→ [`ops/migration-retirement.md`](../ops/migration-retirement.md)

---

## `mdns` · `.local` 自动发现

macOS 和多数 Linux 桌面开箱支持，不用配任何东西，`主机名.local` 就能访问。

**但不要指望它覆盖全部设备**：

| 平台 | 支持 |
|---|---|
| macOS / iOS | ✅ 原生 |
| Linux 桌面 | ✅ 通常装了 Avahi |
| Windows | ⚠️ 较新版本支持，旧版要装 Bonjour |
| Android | ⚠️ 系统层支持不完整，很多 App 解析不了 |
| 电视 / 机顶盒 | ❌ 基本别想 |

⚠️ **`.local` 是 mDNS 保留后缀（RFC 6762）。**
**绝对不要**把 `.local` 拿来当普通 DNS 后缀用——两套解析机制会打架，
症状是"有的设备能解析、有的不能"，而且极难诊断。

**结论**：`mdns` 是白拿的便利，不是可依赖的方案。**别把它当成 `lan-dns` 的替代。**

---

## `lan-dns` · 局域网 DNS

给内网服务一套域名，由局域网里的 DNS 负责解析。**服务多起来之后这是正解。**

- ✅ **一处改，全屋生效**——IP 变了只改一条记录
- ✅ 所有设备都吃（DNS 是最通用的机制，电视也认）
- ✅ 配合反向代理，可以做到"一个域名一个服务"，不用记端口
- ✅ **能签真证书**（见下），于是内网也能上 HTTPS

### 用什么后缀

这是个真判据，选错了要返工：

| 后缀 | 评价 |
|---|---|
| **你拥有的真实域名的子域**（`home.example.com`） | ✅ **推荐**。能签真证书，永远不会和公网冲突 |
| `home.arpa` | ✅ RFC 8375 专为家庭网络保留，安全但**签不了公开信任的证书** |
| `.internal` | ✅ ICANN 已指定为私有使用，同上，签不了证书 |
| `.local` | ❌ **mDNS 保留**，会打架 |
| `.lan` / `.home` / 自己编的 | ⚠️ 没有正式保留，将来可能被注册成真 TLD 而冲突 |
| 你**不拥有**的真实域名 | ❌ 会劫持真实站点，且无法解释的故障 |

> **有域名就用自己域名的子域。** 这是唯一能同时满足"不冲突"和"能签证书"的选项，
> 而且域名本身很便宜。没有域名就用 `home.arpa`。

### 证书怎么来

内网 IP 签不了公开证书，但**用你自己域名的子域可以**——
通过 DNS 验证方式签发，不需要这台机器暴露在公网上。
签出来的证书对内网 IP 同样有效，因为验证的是**域名所有权**，不是可达性。

具体做法看你用的反代与证书工具的文档。→ [层 6](6-ingress.md#反向代理与证书)

### 在哪跑这个 DNS

按省事程度：

1. **主路由自带的静态 DNS 记录** —— 很多路由器支持，零额外维护。**先看有没有**
2. **专门的局域网 DNS 服务** —— 功能全，但多一个要维护的常驻服务
3. **旁路由上的 DNS**（如果你有旁路由）—— 顺手，但**把内网寻址绑在了旁路由的可用性上**

⚠️ 第 3 种要想清楚：旁路由挂了，不只是没代理，**连内网服务的名字都解析不了**。
把两个故障绑在一起会让排查变难。

## 与其它层的交互

### 与层 4（如果你有代理）

**透明代理的 fake-ip 会吃掉你的内网域名**，让它解析成假地址。
配好内网域名之后**必须**把这个后缀加进 fake-ip 过滤列表。

→ [层 4 · 坑一](4-routing-dns.md#坑一局域网服务访问不了裸主机名)

这是本手册里最常见的"配好了但访问不了"，而症状（502 / 连接超时）完全不指向 DNS。

### 与层 6（如果你要外网访问）

同一个域名，**内网解析到内网 IP、外网解析到公网入口**——这叫分离解析。
好处是内外用同一个地址，客户端不用切换。

⚠️ 两边要**分别配、分别验**。只测了一边就上线，是很常见的疏漏。

## 验收

```yaml
verify: |
  # ★ 从【另一台设备】跑，而且要挑一台"最难的"——
  #   电视或 Android 手机，不要用你自己的开发机

  # 1. 名字能解析
  nslookup service.example.com
  # 期望: 返回你服务器的内网 IP（不是 198.18.x.x 的 fake-ip、不是公网 IP）

  # 2. 名字能访问
  curl -s -o /dev/null -w '%{http_code}\n' https://service.example.com
  # 期望: 200 或 401

  # 3. 换一台设备再来一次（尤其是电视 / Android）
  #    "我的电脑能开"不等于全屋能开——mDNS 场景下这条几乎必然翻车
```

⚠️ **第 3 条不能省。** 内网寻址最典型的失败就是"在我这儿好好的"，
而恰恰是电视、老设备、Android 这些解析能力差的客户端会翻车——
**它们又正好是最需要好记地址的那些。**
