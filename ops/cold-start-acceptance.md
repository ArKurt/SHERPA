# 冷启动验收

> 一份清单。配完开机自恢复之后**真的断电重启一次**，逐项走完。
>
> **不重启验证的自启动配置，等于没配。**

## 什么时候做

- 配完 [`boot-persistence.md`](boot-persistence.md) 之后
- 每次改动启动链之后
- 系统大版本升级之后
- **搬家、换电源、换 UPS 之后**

## 怎么做

**真的断电**，不是软重启。软重启保留了很多状态（挂载、已解锁的加密卷），
测不出真实的冷启动行为。

⚠️ 断电前先确认：**如果它起不来，你有办法进去修。**
物理接触得到机器，或者有另一条不依赖它的网络路径。

## 清单

### 阶段 0 · 加电后、无人干预

- [ ] 机器通电自动开机（还是需要按电源键？）
- [ ] 如果开了全盘加密：**它停在解锁界面**——这是预期行为，不是故障。
      记下"此刻有哪些东西不可用"

### 阶段 1 · 登录、解锁后

- [ ] 容器运行时启动
- [ ] 所有容器按重启策略回来了
- [ ] 原生服务回来了
- [ ] **虚拟机回来了**，且**只有一个实例**
      （`ps` 确认没有两个虚拟机进程抢同一块磁盘）

### 阶段 2 · 存储

- [ ] 所有外接盘/网络挂载都挂上了
- [ ] 挂载点路径和之前一致（有些系统会加 `-1` 后缀）
- [ ] **服务看到的是真实数据，不是空目录**
      —— 这条最重要。挂载晚于服务启动时，服务可能已经在空目录上初始化过了

### 阶段 3 · 网络

- [ ] 旁路由的 IP 是预期的那个
- [ ] 旁路由的 DHCP 服务**是关的**
- [ ] 从一台**客户端**测：能出网、且走的是预期出口
- [ ] 组网工具重新连上了
- [ ] **路由表里没有指向不存在设备的残留条目**
      → [层 6 · 幽灵路由](../pitfalls/boot-ops.md#幽灵路由退役设备留下的影子)

### 阶段 4 · 入口（如果有）

- [ ] 隧道客户端重连成功
- [ ] **从外网**访问一个服务，返回预期状态
- [ ] 证书有效，自动续签任务在跑

### 阶段 5 · 应用

- [ ] 逐个服务跑它自己的 `verify`（**从客户端**）
- [ ] 定时任务回来了（备份、清理、DNS 更新）

## 记录结果

把"哪些需要人工干预才能恢复"记下来。**这份清单本身就是价值**——
下次真的断电时，你知道该做什么，而不是从零排查。

特别记下：

- 冷启动到完全可用需要多久
- 哪些步骤必须有人在场
- 哪些服务的恢复有先后依赖

## 如果有些东西没回来

不要现场手工拉起来就算完——**那只是掩盖问题**。
找到为什么没自启，修好，再冷启动一次验证。
