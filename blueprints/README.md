# 参考架构（锚点）

拿 [`00-probe.md`](../00-probe.md) 产出的配置向量来这里对号入座。
**对得上**就走那条已验证路径；**对不上**再去 [`layers/`](../layers/) 逐层求解。

> **对不上是常态，不是异常。** 锚点是加速器，不是选项清单。

## 快速排除

| 锚点 | 状态 | 前提 | 不适用于 |
|---|---|---|---|
| [A · 老笔记本一肩挑](a-single-laptop.md) | 已验证 · **已退役** | 一台闲置 x86 机器；接受一切塞进一个 VM | 不需要代理的人；想要故障隔离的人 |
| [B · 混合](b-hybrid-mini.md) | 已验证 · **在用** | 机器性能够；**要两个网口**；接受维护两套 | 单网口机器；不需要旁路由的人 |
| [C · NAS 底座](c-nas.md) | ⚠️ **未落地验证** | 有一台支持虚拟化的 NAS | 没有 NAS 的人 |

⚠️ **三条锚点全部包含旁路由。** 如果用户不需要代理
（[`00-probe.md` Q2a](../00-probe.md#q2a-需不需要代理)），
**三条一条都不会对上**——这不是问题，直接去 [`layers/`](../layers/) 求解。
实际要读层 1、层 5、层 7；有外网再加层 6；层 2/3/4 整片跳过。
**不要为了对上某条锚点而引入代理。**

硬件形态接近 [锚点 B](b-hybrid-mini.md)（Apple Silicon、服务原生跑）时，
对不上也请读 B 的
[「没有旁路由的话，这些代价哪些仍然适用」](b-hybrid-mini.md#没有旁路由的话这些代价哪些仍然适用)
——睡眠和 FileVault 跟旁路由无关。

## A 和 B 与 C 的区别

A、B 是"**这么干过，代价是这些**"——代价那几节是它们的主要价值。
C 是"**应该这么干，但你是第一个**"——推理链完整，没有真机验证过。
用 C 的时候把这个差别放在心上。
