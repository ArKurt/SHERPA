# 代理与分流的坑

> 相关层：[层 3 · 代理栈](../layers/3-proxy-stack.md) · [层 4 · 分流与 DNS](../layers/4-routing-dns.md)
>
> 这几个坑的共同点：**症状不指向真凶**，而且组件自测全是绿的。

## 裸核模式：核能出海，客户端全断

### 症状

- 插件面板显示运行中 ✅
- 在**路由器上**测代理端口，能出海，返回 204 ✅
- **客户端把网关指过来，国内外全断** ❌
- 严重时连路由器管理界面都像打不开

### 原因

代理插件普遍有一个"**只启动内核**"的模式（不同插件叫法不同：裸核、core only、仅内核）。
原型阶段单机验证内核时它很方便，切到旁路由时**极容易忘记关掉**。

裸核模式下，插件只当内核的启动器，**它的混入配置和防火墙规则全部不生效**。于是：
没有对外的控制接口、没有透明代理监听端口、一条流量劫持规则都没有、没有 tun 设备。

客户端的流量既不被透明代理接管，又在单臂发夹转发时撞上防火墙的转发拒绝规则——**两条路都断**。

### 修法

关掉裸核模式，然后**逐项确认集成件都在**（只确认"服务已重启"不够）：

- [ ] 对外控制接口在监听
- [ ] 透明代理端口（重定向 / tproxy）在监听
- [ ] tun 设备已创建并 UP（如果用 tun 模式）
- [ ] 防火墙里有劫持规则，且**数量不为零**
- [ ] 策略路由规则存在

### 教训

> **「核能出海」≠「客户端能借道」。**

这条是本手册**所有 `verify` 字段都要求从客户端视角写**的直接来源。
agent 比人更容易停在"自测通过"就宣布完成。

## fake-ip 三连

透明代理默认开 fake-ip：DNS 不做真实解析，返回一个保留段里的假地址
（通常在 `198.18.0.0/15`），等流量真发出来时代理再按域名建连接。

这么做是为了**让代理拿到域名**——否则客户端先解析出真实 IP 再连，按域名写的规则全失效。

代价是：**任何"拿到 IP 后自己去连"的东西都会拿到假地址。** 下面三个都是这个代价的变体。

### 之一 · 局域网服务访问不了

**症状**：局域网里用主机名访问自己的服务（`http://myserver:8080`）失败，
用 IP 访问正常。反代场景下常表现为 502。

**原因**：裸主机名被送进了代理的 DNS。代理不认识它，没有上游能解析，于是给了个 fake-ip。
客户端拿着 `198.18.x.x` 去连——那里什么都没有。

**修法**（按可靠性排序）：

1. **在 fake-ip 过滤列表里加上你的本地域**（`*.lan`、`*.local` 或你自定义的后缀）
2. **给内网服务用真实的本地域名**，而不是裸主机名，配合上一条
3. **客户端 hosts 硬编** —— 最快，但每台设备都要做。当止血用，别当方案

⚠️ 过滤列表往往是**整表替换**语义：一旦你自定义了它，插件内置的那些条目
（常见的游戏机域名等）就不再生效，要一并补齐。

→ 内网该怎么起名字，见 [层 7](../layers/7-lan-addressing.md)

### 之二 · 组网工具的域名被吃掉

**症状**：装了 Tailscale / ZeroTier 一类的组网工具，**用它们的 IP 能连，用名字连不上**。

**原因**：同上，`*.ts.net` 这类名字被拦下给了 fake-ip。

注意**路由层通常本来就是对的**——代理插件默认把 `100.64.0.0/10` 和 `fc00::/7`
列在保留网段里直连，不劫持。**坏的只有名字解析这一层。**
所以症状是"IP 能通、名字不通"，很容易误判成组网工具本身的问题。

**修法**（两件事都要做，缺一不可）：

1. **DNS 策略**：把 `*.ts.net` 这类后缀指向组网工具自己的 DNS 服务器
   （Tailscale 是 `100.100.100.100`）
2. **fake-ip 过滤**：把同样的后缀加进过滤列表，否则策略解析出真实 IP 后还是会被换成假的

⚠️ 很多插件的这两项**各自带一个默认关闭的总开关**。只填了列表没开开关 = 白填。

⚠️ **把设备的网关切到旁路由之前，先解决这个。** 否则组网工具会在切换的瞬间失联，
而你可能正靠它远程管理这台设备。

### 之三 · 两套 DNS 劫持打架

**症状**：DNS 解析结果随机、时对时错，重启后表现又变了。

**原因**：路由系统自带的 DNS 服务（dnsmasq 一类）常有个"DNS 重定向"选项，
把客户端的查询劫持到自己这里；而代理插件也在做同样的事。
**两套劫持同时开，谁生效取决于防火墙规则的顺序**，结果不可预测。

**修法**：关掉路由系统自带的那个，让代理插件独占 DNS 劫持。
多数代理插件的文档里都明写了这一条，但它不在安装步骤里，容易漏。

## 兜底链路把服务静默杀死

### 症状

**没有任何配置变更**，某个服务某天开始不可用。可能表现为"用着用着掉登录"，
而不是干脆连不上。过几天又自己好了。

### 原因

订阅的兜底规则通常是"其它所有流量 → 某个自动选择组"，而自动组按延迟挑节点——
**延迟最低的往往是离你最近的地区**。

如果某个服务屏蔽了那个地区，自动组一漂过去，服务立刻失效。
触发条件是**网络延迟的自然波动**，所以它不可复现、也不报错。

已知实例：**Anthropic（Claude）屏蔽香港**，OpenAI 有类似的地区限制；各家流媒体同理。

### 修法

给这类服务**单独建组、手工指定地区，组里不放自动选项、不放被屏蔽的地区**，
并把规则放在规则表最前面。

具体配法见 [层 4 · 地区敏感服务](../layers/4-routing-dns.md)。

### 教训

> 任何"其它情况走 X"的兜底，都要问一句：**X 会漂到哪里去？**

## 社区规则集过期，漏掉关键域名

### 症状

某个服务**用着用着掉登录**，而不是连不上。重新登录后又能用一阵。

### 原因

现成的规则集很方便，但会过期。真实案例：某广泛使用的规则集里，Claude 相关只有 **3 条**、
一年多没更新，**漏掉了负责 OAuth 令牌刷新的那个域名**。

漏这个域名尤其阴险——它不影响建立连接，只影响**续期**，所以表现是"用一阵就掉"，
几乎不可能联想到分流上。

### 修法

对**域名少而稳定**的服务（一年变不了一次），直接照官方文档的 allowlist 写死后缀。

找官方 allowlist 的关键词：`<服务名> network configuration` / `firewall allowlist`
/ `allowed domains`。

### 教训

> 社区规则集**用之前看两件事：最后更新日期、条目数**。
> 引入一个会过期的外部依赖，比自己写死几条后缀更不可靠。

## 并装了两套透明代理

### 症状

两个插件的面板都显示运行中，**但客户端连不上任何东西**。
每个组件单独看都正常。

### 原因

两套会各自往防火墙里塞流量劫持规则，互相覆盖、互相打架。
流量被 A 劫走、按 B 的规则处理，或者反过来。

### 修法

**只装一套。** 想换栈就先彻底卸掉旧的（包括它写进防火墙的规则和开机自启），
确认防火墙干净，再装新的。

这条在手册里是 `conflicts` 硬约束，不是建议。→ [层 3](../layers/3-proxy-stack.md)
