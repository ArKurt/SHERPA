# 凭证与密钥

> 这一页是给**会实际经手这些密钥的人和 agent** 看的。
> 手册的其它地方零散提过"这个别入库""那个要设密码"，集中在这里说清楚。

## 一条铁的规则

```
凭证不进版本库。任何版本库，包括私有的。
```

私有仓库**将来可能转公开**，而 git 历史里的东西**删不干净**——
你可以删掉那一行，但它永远留在某个 commit 里。
"以后再清理"这件事在 git 上不成立。

同理：不进任何会同步到别处的目录（云盘、共享盘、公开的知识库）。

## 你会经手哪些

| 类型 | 例子 | 泄露后果 |
|---|---|---|
| **订阅链接** | 代理订阅 URL | 别人白嫖你的流量；有些机场会因此封号 |
| **服务密钥** | 下载器的 RPC secret、代理控制接口的 token | **任意写文件**、任意改配置 |
| **隧道凭证** | 公网入口服务商给的凭证文件 | 别人能把流量接到你的域名上 |
| **API 密钥** | AI 服务、DDNS 服务的 token | **直接产生费用**，且可能很大 |
| **应用口令** | 各服务的管理员密码、反代的认证 | 视服务而定，密码库最严重 |
| **SSH 私钥** | 进服务器的钥匙 | 全盘失守 |

## 放哪

按可靠程度递增：

### 1. 环境变量文件（起步够用）

容器编排普遍支持一个存放变量的文件，配置里只写变量名，实际值在那个文件里。

必须做的两件事：

- **把这个文件加进 `.gitignore`**，并确认它真的没被跟踪
- **收紧文件权限**，只让运行服务的那个用户读

⚠️ 常见疏漏：`.gitignore` 加了，但文件**在加之前就已经被 git 跟踪了**——
`.gitignore` 对已跟踪文件无效。加完之后**确认一遍**。

### 2. 密码库（服务多了之后）

Vaultwarden 一类的自托管密码库可以当作凭证的落点。
→ [`../services/vaultwarden.md`](../services/vaultwarden.md)

⚠️ 但注意**循环依赖**：密码库本身的主密码和恢复方式**不能只存在密码库里**。
那把钥匙要单独安置——纸质、离线介质、或者你脑子里。

### 3. 系统密钥环 / 专用密钥管理

更规范，但对家用规模通常是过度设计。**服务少的时候别上。**

## 怎么传给服务

| 方式 | 评价 |
|---|---|
| 环境变量文件 | ✅ 常见做法，够用 |
| 挂载成文件（容器里读文件） | ✅ 比环境变量更好——环境变量会出现在进程列表和日志里 |
| **写死在配置文件里，配置文件进 git** | ❌ 就是这条规则要防的事 |
| **写在命令行参数里** | ❌ **任何能看进程列表的人都能看到** |

最后一条容易中招：下载器的 RPC 密钥如果作为命令行参数传，
同机的任何进程 `ps` 一下就能看到。**优先用配置文件或环境变量。**

## 备份里怎么处理

**凭证也要备份**——否则灾难恢复时你有数据没钥匙，等于没备份。

但备份介质的安全性通常低于原机（外接盘、异地、云）。所以：

- 含凭证的备份**要加密**
- 加密口令**不能和被备份的凭证放在一起**
- → [`backup.md`](backup.md)

## 轮换

出现下列情况时**换掉**，不要犹豫：

- 你把它粘进过聊天窗口、issue、或任何你不完全控制的地方
- 它曾经进过 git（**即使已经删了那一行**）
- 离职 / 换人 / 设备丢失
- 服务商通知有泄露

⚠️ **轮换要连带更新所有用到它的地方**，否则会出现"改了一半"的半失效状态，
症状是部分功能好、部分不好，很难查。**换之前先列出用到它的清单。**

## 给 agent 的额外要求

如果你是读这份手册、在用户机器上实施的 agent：

- **不要把用户的凭证写进任何会被提交、上传或分享的地方**，包括你自己的工作笔记
- **不要在回复里回显完整凭证**——需要确认时只显示前后几位
- 需要用户提供凭证时，**说明它会被写到哪个文件、那个文件受什么保护**
- 用户让你"记下来"的时候，记的应该是**它在哪**，不是它是什么
