# 存储的坑

> 相关层：[层 5 · 存储](../layers/5-storage.md)
>
> 这几个坑的共同点：**原始数据其实都没丢**，坏的是承载它的东西。

## 数据库和媒体库同盘，盘一走就崩溃循环

> 📌 **这一节是[锚点 A](../blueprints/a-single-laptop.md) 上一次事故的复盘**，
> 不是 USB 盘或数据库的普适故障序列（当时的系统与数据库版本没记录）。
> 具体观察都是真的，**别把它当成"一定会这样"**。

### 症状

服务起不来，数据库容器**反复重启**——累计达到几千次。
日志里是"磁盘空间不足"和反复的初始化失败。

而 **SMART 全绿**，盘体看起来完全正常。

### 原因

数据库和照片库放在同一块 USB 直通的移动硬盘上。那块盘被物理搬走之后，
**挂载点变成了一个空的临时文件系统**（几 MB 大小）。

数据库看到一个空目录，以为自己是全新安装 → 开始初始化 → 空间不足 → 失败 → 重启 → 再初始化。

**原始照片一个字节都没丢**，只是不在那儿了。

### 更深一层的原因

那块盘长期承受**频繁的异常断电**（USB 供电不稳、主机睡眠时总线掉电、线松）。
盘体没老化，但它上面的文件系统被反复损坏，靠反复修复续命。

对媒体文件，掉一次就是"这个视频暂时播不了"。
对数据库，掉一次可能就是文件系统损坏，**而数据库还在往里写**。

### 修法

**把数据库留在内置盘上，只把媒体文件放外接盘。**

⚠️ **前提是这个服务支持拆分——逐个查，别假设。**
状态数据通常比媒体小得多，内置盘一般放得下；但**具体多大按服务文档和现场实测**，
别套一个统一的数字（比如 Immich 的 Postgres 现行文档说通常就有 1–3 GB）。

### 教训

> **最重要的那部分数据，通常是最小的那部分。**
> 别因为"整齐"把它跟着媒体一起挪到会掉线的盘上。

## exFAT 上的容器写入，改目录权限没用

### 症状

服务启动正常，但**一写就报权限错误**。在宿主上 `chown` / `chmod` 那个目录，重启容器，照旧。

### 原因

exFAT **不存逐文件的属主和权限位**——格式里根本没有这两个字段。
所以在挂载点里 `chown` 是无效操作：写进去的东西不会被保存，重挂之后一切照旧。

最容易中招的是**相册类服务的上传目录**：它看起来和影音库一样是"一堆大文件"，
但它是容器要以非 root 身份**持续写入**的目标，而影音库通常只读挂载。

### 修法

属主不是在目录上设的，**是在挂载时一次性设定整卷的**：

```sh
# Linux exFAT 驱动支持这些参数（fs/exfat/super.c）
mount -t exfat -o uid=1000,gid=1000,fmask=0133,dmask=0022 /dev/sdX1 /挂载点
# 1000:1000 换成目标容器实际运行的 UID:GID
```

然后**从容器里**验收，不是从宿主：

```sh
docker compose exec <服务> sh -c 'touch /挂载点/.wtest && rm /挂载点/.wtest' && echo OK
# 期望: OK
```

**这条路走不通的三种情况**（此时才考虑重新格式化，而格式化会擦盘，必须问用户）：

1. **多个服务或多个用户共写这块盘** —— 全卷只有一个属主，给了谁都不对
2. **服务自己要 `chown` / `chmod`，或要建硬链接** —— exFAT 给不了
3. **数据库、索引、服务状态** —— 与权限无关，是 exFAT 基础格式无日志，异常关机后可能损坏

### 教训

> **"改不动权限"和"写不进去"是两回事。**
> exFAT 确实不存权限，但它能被挂载成某个用户可写。
> 先分清你缺的是"逐文件权限"还是"能写"——只缺后者的话，不必擦盘。

## 服务起来了，但看到的是空目录

### 症状

服务正常运行，界面能开，**但一条数据都没有**。
更糟的情况：它把宿主上那个空目录当成全新安装，**写了一套新数据进去**。

### 原因

外接盘或网络挂载**晚于服务启动**才就绪。服务启动时挂载点还是个空目录，
它按"全新安装"处理。

⚠️ **真正的盘随后挂上来时，新写的那套数据会被盖在下面**——
你原来的数据通常还在，只是被遮住了。但**会不会被真正覆盖掉，取决于这个服务
后续怎么写**，别当成通用结论；先按"数据可能还在"去查，不要急着从备份恢复。

### 修法

配置显式的挂载依赖或启动前等待。冷启动验收时**专门检查这一条**——
见 [`ops/cold-start-acceptance.md`](../ops/cold-start-acceptance.md)。

### 教训

> 冷启动验收清单里"服务看到的是真实数据，不是空目录"这条，
> 就是为这个坑写的。**只确认"服务起来了"会漏掉它。**
