# 层 4 · 分流与 DNS

> 代理装起来只是开始。**决定好不好用的是这一层**，而它的坑比其它层加起来还多。
> 这一层的每个坑都有同一个特征：**症状不指向真凶**。

## fake-ip：为什么用它，以及它的代价

透明代理普遍默认开 fake-ip：DNS 查询不做真实解析，而是返回一个保留段里的假地址
（通常在 `198.18.0.0/15`），等流量真的发出来时，代理再按域名去建连接。

这么做是为了**让代理拿到域名**——如果客户端先解析出真实 IP 再连，代理就只看得到 IP，
按域名写的规则全都失效。

代价是：**任何"拿到 IP 后自己去连"的东西都会拿到假地址**。下面三个坑都是这个代价的变体。

---

## 坑一：局域网服务访问不了（裸主机名）

### 症状

局域网里用主机名访问自己的服务（`http://myserver:8080`）失败，
用 IP 访问（`http://192.0.2.10:8080`）正常。反代场景下常表现为 502。

### 原因

裸主机名被送进了代理的 DNS。代理不认识它，没有上游能解析，于是给了个 fake-ip。
客户端拿着 `198.18.x.x` 去连——那里什么都没有。

### 修法

按可靠性排序：

1. **在 fake-ip 过滤列表里加上你的本地域**（`*.lan`、`*.local` 或你自定义的后缀），
   让这些名字走真实解析
2. **给内网服务用真实的本地域名**，而不是裸主机名，配合上一条
3. **客户端 hosts 硬编**——最快，但每台设备都要做，且 IP 变了要手工改。当止血用，别当方案

⚠️ 注意过滤列表往往是**整表替换**语义：一旦你自定义了它，插件内置的那些条目
（常见的游戏机域名等）就不再生效，要一并补齐。

---

## 坑二：组网工具的域名被吃掉

### 症状

装了 Tailscale / ZeroTier 一类的组网工具，**用它们的 IP 能连，用它们的名字连不上**。

### 原因

同上——`*.ts.net` 这类名字被代理的 DNS 拦下给了 fake-ip。

注意**路由层通常本来就是对的**：代理插件默认把 `100.64.0.0/10`（Tailscale 用的 CGNAT 段）
和 `fc00::/7` 列在保留网段里直连，不劫持。**坏的只有名字解析这一层。**
所以症状是"IP 能通、名字不通"——很容易误判成组网工具本身的问题。

### 修法

两件事都要做，缺一不可：

1. **DNS 策略**：把 `*.ts.net` 这类后缀指向组网工具自己的 DNS 服务器
   （Tailscale 是 `100.100.100.100`）
2. **fake-ip 过滤**：把同样的后缀加进过滤列表，否则策略解析出真实 IP 后还是会被换成假的

⚠️ 很多插件的这两项各自带一个**总开关**，默认是关的。只填了列表没开开关 = 白填。
改完务必回头确认开关状态。

### 顺序警告

**把设备的网关切到旁路由之前，先解决这个。** 否则组网工具会在切换的瞬间失联，
而你可能正靠它远程管理这台设备。

---

## 坑三：两套 DNS 劫持打架

### 症状

DNS 解析结果随机、时对时错，重启后表现又变了。

### 原因

路由系统自带的 DNS 服务（dnsmasq 一类）常有个"DNS 重定向 / 强制走本机 DNS"的选项，
它会把客户端的 DNS 查询劫持到自己这里。而代理插件也在做同样的事，劫持到自己的端口。

**两套劫持同时开，谁生效取决于防火墙规则的顺序**，结果不可预测。

### 修法

**关掉路由系统自带的那个**，让代理插件独占 DNS 劫持。多数代理插件的文档里都明写了这一条，
但它不在安装步骤里，容易漏。

---

## 地区敏感服务：兜底链路会静默杀死它们

这一节单独拿出来讲，因为它**不报错**。

### 问题

订阅的兜底规则通常是"其它所有流量 → 某个自动选择组"。自动选择组按延迟挑节点，
**而延迟最低的节点往往在离你最近的地区**。

如果某个服务屏蔽了那个地区，结果是：

- 平时好好的（自动组恰好选了别处）
- 某天自动组漂过去了 → 该服务**静默失效**
- **没有任何配置变更**，没人做错任何事
- 表现可能是"用着用着掉登录"，而不是干脆连不上

诊断难度极高，因为触发条件是网络延迟的自然波动。

### 已知的实例

- **Anthropic（Claude）屏蔽香港**，与 OpenAI 的做法一样。自动组一旦落到香港，Claude 立刻不可用
- 各家流媒体的地区限制同理

⚠️ 如果这台旁路由要给 AI agent 用（包括读这份手册的你自己），这条是**功能前提**，不是优化项。

### 修法

给这类服务**单独建一个选择组，手工指定地区，且组里不放自动选项、不放被屏蔽的地区**。

```yaml
# 结构示意，具体语法见你所选插件的文档
proxy-groups:
  - name: <服务名>
    type: select
    proxies:
      - <你确认可用的地区>        # 第一个 = 默认选中
      - <备选地区 1>
      - <备选地区 2>
      # ⚠️ 故意不包含被该服务屏蔽的地区
      # ⚠️ 故意不包含"自动"——自动会漂，正是本组要规避的东西

rules:
  - 'DOMAIN-SUFFIX,<官方域名 1>,<服务名>'
  - 'DOMAIN-SUFFIX,<官方域名 2>,<服务名>'
```

把这条规则**放在规则表最前面**，确保它先于兜底命中。

### 别抄社区规则集（会过期）

现成的规则集很方便，但**用之前看两件事：最后更新日期、条目数**。

真实案例：某广泛使用的规则集里，Claude 相关只有 3 条、一年多没更新，
**漏掉了负责 OAuth 令牌刷新的那个域名**。后果不是连不上——是"用着用着掉登录"，
几乎不可能联想到分流上。

对**域名少而稳定**的服务（一年变不了一次），直接照官方文档的 allowlist 写死后缀，
比引入一个会过期的外部依赖可靠得多。找官方 allowlist 的关键词：
`<服务名> network configuration` / `firewall allowlist` / `allowed domains`。

## 覆写与混入：怎么加自己的规则

订阅是别人给的，会定期更新覆盖。**你自己的规则必须放在订阅之外的地方**，
否则每次更新订阅就丢一次。

多数插件提供"混入 / 覆写"机制，把你的片段合并进订阅配置。要搞清楚的三件事：

1. **合并语义是深合并还是替换？** 深合并意味着你新增的条目是**追加**，不会覆盖订阅原有的；
   替换意味着你写了什么就只剩什么。**猜错会丢掉订阅自带的规则集。**
2. **优先级顺序是什么？** 典型是"订阅 → 混入文件 → 界面配置"，后者覆盖前者
3. **有没有总开关？** 常见陷阱：混入文件**默认是停用的**。只写文件不开开关 = 白写

### 改之前先 dry-run

高风险配置（这台机器是别人的网关）改动前，**先在临时副本上跑一遍合并，检查结果**：

```sh
# 思路示意——具体命令取决于插件
# 1. 把当前生效的配置复制一份到临时位置
# 2. 对副本执行与插件相同的合并逻辑
# 3. 检查关键数字：
# - 规则总数 = 订阅条数 + 你新增的条数？ 验证是追加不是替换
# - 规则集数量 = 订阅原有数量？ 验证深合并没吃掉东西
```

数字对不上就别提交。

## 验证：问内核，别信配置文件

**配置文件里写了什么不算数，内核实际在用什么才算数。**

多数 mihomo 系内核提供一个 HTTP 控制接口，可以直接问它：

```sh
# 生效的规则表（确认你的规则在最前面）
curl -s -H "Authorization: Bearer <API_SECRET>" http://192.0.2.4:9090/rules

# 各代理组当前选中了谁
curl -s -H "Authorization: Bearer <API_SECRET>" http://192.0.2.4:9090/proxies

# ★ 最有用的一个：真实连接命中了哪条规则、走了哪条链
curl -s -H "Authorization: Bearer <API_SECRET>" http://192.0.2.4:9090/connections
```

### 对照实验才算证明

静态看配置不算验证。要**同一时刻两条流量分道**才算证明规则生效：

1. 故意把自动组切到"坏"的地区，构造最坏情况
2. 同时产生两类流量：一条应命中你的专用规则，一条走兜底
3. 查 `/connections`，确认两者走了**不同的链**
4. 再用回显 IP 的服务确认两者的**出口地区确实不同**

只有这样才证明"自动组漂移不会影响被钉死的服务"——这正是你做这件事的目的。

## 保留网段：什么不该被代理

确认这些是直连、不劫持的：

| 网段 | 用途 |
|---|---|
| `192.0.2.0/24`（你的局域网） | 本地服务互访 |
| `100.64.0.0/10` | Tailscale 等组网工具的 CGNAT 段 |
| `fc00::/7` | IPv6 唯一本地地址 |
| `127.0.0.0/8`、`::1` | 本机 |

多数插件默认就包含这些，但**自定义过之后要回头确认没被覆盖掉**。

## 回退

这一层的所有改动都应该能**一条命令退回**，且退回不依赖刚改坏的链路。
改之前先确认：

- 混入/覆写有总开关 → 关掉开关就回到订阅原样
- 配置文件改动前留了备份
- 到旁路由的管理通道是**局域网直连、不经代理**

最后一条最重要：这台机器是别人的网关，配置错会断网，**但你必须还进得去**。
