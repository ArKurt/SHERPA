# 迁移与退役

> 换硬件、搬服务、退掉一台旧机器。
> **这一章的核心观点：退役一台设备时，清理所有指向它的残留配置，和退役本身一样重要。**

## 迁移

### 先做架构预检，再定架构

如果新旧机器架构不同（x86 → ARM 是最常见的），**动手前逐个确认所有容器镜像
都有目标架构的构建**：

```sh
docker manifest inspect <image>:<tag> | grep -A2 architecture
```

这个预检值得单独花时间做，因为**它的结果会改变你的架构决策**：

> 真实案例：迁移前逐个查了全部要用的镜像，确认全部原生可跑。
> 于是服务栈根本不需要套虚拟机，直接原生跑——省掉了一整层复杂度。
> 如果反过来（先决定套 VM，再发现其实不用），就白白背上了这层。

→ [锚点 B · 为什么这么分](../blueprints/b-hybrid-mini.md#为什么这么分)

### 按"怎么迁"分桶，不是按服务分

| 桶 | 内容 | 做法 |
|---|---|---|
| **配置** | 各服务的配置文件 | 平移，改路径 |
| **容器** | 服务本身 | 重新拉镜像、重建 |
| **数据卷** | 数据库、状态 | **先备份，再迁** |
| **大数据** | 媒体、照片 | 能物理拔盘就拔盘，别走网络拷 |
| **连锁依赖** | 别的机器指着它的东西 | **最容易漏，见下** |

⚠️ **物理拔盘远快于网络传输**。几个 T 的媒体，插过去几分钟，走千兆网要一整天。

### 新旧并行，别一次切干净

让新系统先跑起来、对拍验证，**旧的暂时别停**。确认无误再切入口。

⚠️ 但**别让两套同时对外服务**——尤其有状态的服务，两边各自写数据会分叉，
之后无法合并。并行期间只让新系统只读，或者只让一套接受写入。

### 最危险的一步放最后

网络核心（旁路由、入口）**最后迁**。前面所有服务都在旧机器上正常跑着的时候，
网络出问题你还有余地；反过来就没有了。

## 退役

### 幽灵路由——退役最常见的后遗症

一台设备关机了，但**别的机器上还留着指向它的配置**，通常藏在一个**平时不用的网络接口**里。

症状是：某些访问间歇性失败、手动测却是通的、重启服务偶尔"好了"、完全不可复现。

**这是本手册里最难诊断的一个坑。** 完整案例与排查命令见
[坑典 · 幽灵路由](../pitfalls/boot-ops.md#幽灵路由退役设备留下的影子)。
下面的清单就是为了防它。

### 退役清单

关机之前，把所有指向它的东西找出来：

- [ ] **所有机器**的网关设置（包括不常用的网络接口——Wi-Fi、第二张网卡）
- [ ] **所有机器**的 DNS 设置（同上）
- [ ] 路由表里的静态路由
- [ ] hosts 文件里的硬编条目
- [ ] 反向代理的 upstream 配置
- [ ] 主路由上的端口转发、静态绑定、DHCP 保留
- [ ] DNS 记录（本地和公网）
- [ ] 定时任务里的目标地址
- [ ] 组网工具里的节点（离线节点也要清）
- [ ] 版本库的 remote 地址
- [ ] 备份任务的目标或来源
- [ ] 面板/仪表盘里的链接

### 检查方法

```sh
# 每台还在用的机器上：找有没有指向已退役地址的残留
ip route | grep <退役设备IP>          # Linux
netstat -rn | grep <退役设备IP>       # macOS/BSD
grep -rn <退役设备IP> /etc            # 配置文件里的硬编

# macOS 特别注意：每个网络服务的手动配置是分开的
networksetup -listallnetworkservices
# 逐个查 -getinfo 和 -getdnsservers
```

### 别急着删旧系统

关机、拔线、**但保留系统盘**，直到新系统稳定运行一段时间。
迁移时总会漏东西，而"漏了什么"往往要几周后才暴露。

保留期间在文档里注明它是**只读兜底、不再维护**，避免有人误以为它还在服役
而去改它。
