# 占位符约定

本仓库是公开手册，示例里不出现任何真实地址、域名、MAC 或凭证。
统一用下列占位符，**照抄不会连上任何东西**——每一处都要替换成你现场的真实值。

## 网络

| 占位符 | 含义 | 备注 |
|---|---|---|
| `192.0.2.1` | 主路由 | RFC 5737 TEST-NET-1，保留段，永远不会与真实网络冲突 |
| `192.0.2.4` | 旁路由 | |
| `192.0.2.10` | 服务器主机 | |
| `192.0.2.0/24` | 你的局域网段 | 真实环境常见 `192.168.x.0/24` |
| `198.51.100.7` | 客户端设备 | RFC 5737 TEST-NET-2，用于"另一台机器"的场景 |
| `203.0.113.9` | 公网 IP | RFC 5737 TEST-NET-3 |
| `100.64.0.0/10` | Tailscale CGNAT 段 | **这个是真的**，不要替换 |
| `AA:BB:CC:DD:EE:FF` | MAC 地址 | |

## 域名与凭证

| 占位符 | 含义 |
|---|---|
| `example.com` | 你的域名（RFC 2606 保留） |
| `service.example.com` | 某个服务的子域 |
| `<你的订阅链接>` | 代理订阅 URL——**永远不要写进任何仓库** |
| `<API_SECRET>` | 各类密钥 |
| `user@host` | SSH 目标 |

## 为什么用保留段而不是 `192.168.x.x`

`192.168.1.1` 之类看着自然，但正是**真实设备的常见地址**。agent 照抄示例、恰好命中用户
现场的真机，就会对着错误的目标执行——而且症状看起来像"配置生效了但行为不对"，极难往
"抄了示例值"上联想。

RFC 5737 的三段是**协议保证不会被路由**的文档专用地址。抄错立刻连不上，失败得干脆、
容易发现。**失败要响，不要闷。**

## 检查

```sh
scripts/check.sh redaction
```

任何真实内网地址、真实域名、订阅关键词进仓库都应被这条拦下。
