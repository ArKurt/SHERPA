# 凭证与密钥

> 这一页是给**会实际经手这些密钥的人和 agent** 看的。
> 手册的其它地方零散提过"这个别入库""那个要设密码"，集中在这里说清楚。

## 一条铁的规则

```
凭证不进版本库。任何版本库，包括私有的。
```

私有仓库**将来可能转公开**，而 git 历史里的东西**删不干净**——
你可以删掉那一行，但它永远留在某个 commit 里。
"以后再清理"这件事在 git 上不成立。

同理：不进任何会同步到别处的目录（云盘、共享盘、公开的知识库）。

## 你会经手哪些

| 类型 | 例子 | 泄露后果 |
|---|---|---|
| **订阅链接** | 代理订阅 URL | 别人白嫖你的流量；有些机场会因此封号 |
| **服务密钥** | 下载器的 RPC secret、代理控制接口的 token | **任意写文件**、任意改配置 |
| **隧道凭证** | 公网入口服务商给的凭证文件 | 别人能把流量接到你的域名上 |
| **API 密钥** | AI 服务、DDNS 服务的 token | **直接产生费用**，且可能很大 |
| **应用口令** | 各服务的管理员密码、反代的认证 | 视服务而定，密码库最严重 |
| **SSH 私钥** | 进服务器的钥匙 | 全盘失守 |

## 放哪

按可靠程度递增：

### 1. 环境变量文件（起步够用）

容器编排普遍支持一个存放变量的文件，配置里只写变量名，实际值在那个文件里。

必须做的两件事：

- **把这个文件加进 `.gitignore`**，并确认它真的没被跟踪
- **收紧文件权限**，只让运行服务的那个用户读

⚠️ 常见疏漏：`.gitignore` 加了，但文件**在加之前就已经被 git 跟踪了**——
`.gitignore` 对已跟踪文件无效。加完之后**确认一遍**。

### 2. 密码库（服务多了之后）

Vaultwarden 一类的自托管密码库可以当作凭证的落点。
→ [`../services/vaultwarden.md`](../services/vaultwarden.md)

⚠️ 但注意**循环依赖**：密码库本身的主密码和恢复方式**不能只存在密码库里**。
那把钥匙要单独安置——纸质、离线介质、或者你脑子里。

### 3. 系统密钥环 / 专用密钥管理

更规范，但对家用规模通常是过度设计。**服务少的时候别上。**

## 怎么传：两种情形，别混

### 情形一：传给一个长期运行的服务

| 方式 | 评价 |
|---|---|
| 环境变量文件（`.env`） | ✅ 常见做法，够用 |
| 挂载成文件，容器里读文件 | ✅ 更好——环境变量会出现在进程环境和部分日志里 |
| **写死在配置文件里，且该文件进 git** | ❌ 就是本页规则要防的事 |
| **写在服务的启动命令行参数里** | ❌ 同机任何进程 `ps` 一下就看得到 |

### 情形二：传给一条你手敲（或 agent 敲）的命令

**这里有个反直觉的坑，中招率极高。**

> ⚠️ **把密钥放进环境变量，并不能让它离开命令行。**
>
> `curl -H "Authorization: Bearer $TOKEN" …` —— **shell 会先把 `$TOKEN` 展开，再 exec**。
> 真正的密钥值原样进入 argv，`/proc/<pid>/cmdline` 谁都读得到。
>
> 环境变量挡住的是**shell 历史**和"打字时被人看到"，**不是进程列表**。

**正确做法：让凭证走 stdin 或配置文件，绕开 argv。**

```sh
read -rs TOKEN                       # 输入不回显

# ① HTTP 头 / URL —— 用 curl 的配置，从 stdin 读
printf 'header = "Authorization: Bearer %s"\nsilent\n' "$TOKEN" \
  | curl -K - "https://example.com/api"

# ② 请求体 —— -d @- 从 stdin 读
printf '{"token":"%s"}' "$TOKEN" \
  | curl -s -X POST -d @- "https://example.com/api"

unset TOKEN
```

**怎么自己验证有没有泄露**（在 `sh` / `bash` 里跑，不是 fish；
四个分支在 Linux 上逐个实测过，macOS 靠的是 `ps -o args=` 本身可移植）：

```sh
# 让请求挂住，然后查它自己的 argv
curl -s --max-time 8 -H "Authorization: Bearer $TOKEN" http://198.51.100.9:81/ &
pid=$!
args=$(ps -ww -o args= -p "$pid")      # ps 在 Linux 与 macOS 上都能读 argv

case "$args" in
  "")         echo "检查无效：没抓到 argv（进程已退出或 ps 不可用），重跑" ;;
  *"$TOKEN"*) echo "泄露" ;;
  *curl*)     echo "干净" ;;
  *)          echo "检查无效：抓到的不是那条 curl" ;;
esac
wait "$pid" 2>/dev/null
```

把第一行换成 ① 或 ② 的写法，应当输出「干净」；保持上面这条反例，应当输出「泄露」。
**先跑反例确认它真能报出「泄露」**，再去验自己的写法——不然你验的可能是一条永远说干净的检查。

> ⚠️ 三个细节都是为了**不让这条检查假阴性**，改写时别去掉：
> - 用 `ps` 而不是 `/proc/<pid>/cmdline` —— **macOS 没有 `/proc`**，读不到就等于每次都报「干净」
> - 用 `case` 而不是 `grep -q "$TOKEN"` —— 后者会把令牌塞进 `grep` 自己的 argv
> - `ps -ww` 不截断 —— 截断掉的那半里如果有令牌，同样报「干净」
>
> 抓不到 argv 时它输出「检查无效」而不是「干净」。
> **一条无论如何都会通过的检查，比没有检查更危险**——它会给你一份虚假的安全保证。

⚠️ **agent 尤其要注意这一条**：你的执行环境很可能会把完整命令记进日志或对话历史。
即使 argv 干净了，**命令文本本身**如果含密钥，一样泄露。
所以密钥要从 `read -rs` 或已有的环境里来，**不要出现在你写出的命令字面里**。

## 备份里怎么处理

**凭证也要备份**——否则灾难恢复时你有数据没钥匙，等于没备份。

但备份介质的安全性通常低于原机（外接盘、异地、云）。所以：

- 含凭证的备份**要加密**
- 加密口令**不能和被备份的凭证放在一起**
- → [`backup.md`](backup.md)

## 轮换

出现下列情况时**换掉**，不要犹豫：

- 你把它粘进过聊天窗口、issue、或任何你不完全控制的地方
- 它曾经进过 git（**即使已经删了那一行**）
- 离职 / 换人 / 设备丢失
- 服务商通知有泄露

⚠️ **轮换要连带更新所有用到它的地方**，否则会出现"改了一半"的半失效状态，
症状是部分功能好、部分不好，很难查。**换之前先列出用到它的清单。**

## 给 agent 的额外要求

如果你是读这份手册、在用户机器上实施的 agent：

- **不要把用户的凭证写进任何会被提交、上传或分享的地方**，包括你自己的工作笔记
- **不要在回复里回显完整凭证**——需要确认时只显示前后几位
- 需要用户提供凭证时，**说明它会被写到哪个文件、那个文件受什么保护**
- 用户让你"记下来"的时候，记的应该是**它在哪**，不是它是什么
