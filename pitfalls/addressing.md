# 内网寻址的坑

> 相关层：[层 7 · 内网寻址](../layers/7-lan-addressing.md)
>
> 这几个坑的共同点：**"在我这儿好好的"**。翻车的总是别人的设备。

## 我的电脑能开，电视和安卓打不开

### 症状

你自己的 Mac 或 Linux 机器上，`主机名.local` 访问服务完全正常。
换到电视、机顶盒、Android 手机上——打不开，报"找不到服务器"。

### 原因

`.local` 靠 mDNS 自动发现，而**支持程度差别很大**：

| 平台 | 支持 |
|---|---|
| macOS / iOS | ✅ 原生 |
| Linux 桌面 | ✅ 通常装了 Avahi |
| Windows | ⚠️ 较新版本支持，旧版要装 Bonjour |
| Android | ⚠️ 系统层支持不完整，很多 App 解析不了 |
| 电视 / 机顶盒 | ❌ 基本别想 |

而**电视和老设备恰恰是最需要好记地址的那些**——你不会想在电视遥控器上敲 IP。

### 修法

需要全屋覆盖就上**局域网 DNS**，别指望 mDNS。
mDNS 是白拿的便利，不是可依赖的方案。

### 教训

> **验收要挑一台"最难的"设备做**，不要用你自己的开发机。

## 内网域名解析时对时错

### 症状

同一个内网域名，有的设备解析得到、有的解析不到；同一台设备时好时坏。

### 原因

把 `.local` 拿来当**普通 DNS 后缀**用了。

`.local` 是 mDNS 保留后缀（RFC 6762）。系统看到 `.local` 会走 mDNS 那条路，
而你配的是单播 DNS——**两套解析机制同时存在，谁生效不确定**。

### 修法

换一个后缀。选择判据见 [层 7](../layers/7-lan-addressing.md)：

- **有自己的域名** → 用它的子域（唯一能同时满足"不冲突"和"能签证书"的选项）
- 没有 → `home.arpa`（RFC 8375 专为家庭网络保留）或 `.internal`（ICANN 已指定为私有使用）
- **绝不要** `.local`；也别用 `.lan` / `.home` 这类没有正式保留的

## 服务器 IP 变了，全屋客户端一起失效

### 症状

某天所有设备突然都连不上服务了。手机 App、电视、书签，全部失效。

### 原因

只做了 `hosts-file`（每台客户端硬编）或者干脆让大家记 IP，
而服务器的地址**没有固定**——重启后 DHCP 分了个新地址。

### 修法

两件事：

1. **固定 IP** —— 主路由按 MAC 绑定，或机器上配静态并避开 DHCP 池。
   最稳是**两边都做**，互为保险
2. **上局域网 DNS** —— 之后地址再变，只改一条记录，不用挨个设备改

### 教训

> `hosts-file` 是止血手段，不是方案。设备数一多就是维护灾难，
> 而手机和电视基本做不了。

## 退役设备留下的解析残留

### 症状

某些访问间歇性失败，另一些正常。手动测是通的，服务进程却连不上。

### 原因

hosts 文件里、或某台机器的 DNS 设置里，还留着指向已退役设备的条目。

完整案例见 [启动与运维的坑 · 幽灵路由](boot-ops.md#幽灵路由退役设备留下的影子)。

### 修法

退役设备时按清单逐项清理——
见 [`ops/migration-retirement.md`](../ops/migration-retirement.md)。
